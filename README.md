# probeglass-docs

The documentation site for [ProbeGlass](https://github.com/j000k3r/probeglass),
a small self-hosted watchdog for your homelab. Built with
[Docusaurus](https://docusaurus.io/), published to GitHub Pages.

**Live site:** <https://j000k3r.github.io/probeglass-docs/>

## Why a separate repository

The code and the manual have different rhythms. A release is a tag and a binary; a
docs fix is a typo at midnight. Keeping them apart means the documentation can be
rebuilt and redeployed without touching the code repository's history, and the code
repository stays what it should be: source.

The code repository keeps the documents that live *with* the code —
`README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, and
`docs/ARCHITECTURE.md`, `docs/CONFIGURATION.md`, `docs/ROADMAP.md`. Everything a
user reads is here.

## Running it locally

Requires Node.js 18 or newer.

```bash
npm install
npm start          # dev server on http://localhost:3000, hot reload
```

```bash
npm run build      # static site into ./build
npm run serve      # serve the built site locally, to check it before pushing
npm run clear      # drop the cache if something looks stale
```

`npm start` is the loop you want: edit a Markdown file under `docs/`, and the
browser updates.

## Layout

```
docs/                     the documentation, one file per page
  intro.md                the landing page (slug: /)
  getting-started/        install, first sensor, demo data
  concepts/               sensors, alerts, history, incidents, security
  configuration/          precedence, file, environment, dashboard
  operations/             backup, upgrading, reverse proxy, troubleshooting
  reference/              HTTP API, command line, FAQ
  development/            architecture, contributing, roadmap
sidebars.js               the reading order — hand-written, not generated
docusaurus.config.js      site metadata, url/baseUrl, navbar, footer
src/css/custom.css        theme overrides
static/img/               logo, favicon, social card, and the screenshots
```

`routeBasePath` is `/`, so `intro.md` with `slug: /` is the site root and every
other page is at its own path without a `/docs` prefix.

### The screenshots

Most of the images in `static/img/` are real captures of the running product, not
drawings: a database seeded with `seed --demo --days 7`, served, and photographed
in a browser at 1440px, dark theme. They are regenerated by hand when the
interface changes, which is why several pages say what the picture shows rather
than describing the layout in prose that would then drift.

The three files in `static/img/` that are not screenshots are the drawn ones, and
`docusaurus.config.js` is the only thing that uses them: `favicon.svg` for the
browser tab, `logo.svg` for the navbar, and `social-card.svg` for the preview
image a link to these pages unfurls into. No page references them, which is why
replacing any of them is a one-file change.

## Adding a page

1. Write the Markdown file under `docs/`, with frontmatter:

   ```markdown
   ---
   id: my-page
   title: My page
   sidebar_label: My page
   description: One sentence, used for search results and social previews.
   ---
   ```

2. Add its id to `sidebars.js`, in the position you want it read. The sidebar is
   written out by hand rather than generated from the folder tree, because the
   order a new user should read the pages in should not change when a file is
   renamed or when alphabetical order puts "Architecture" before "Installation".

Nothing else. The build fails on an unknown sidebar id and on a dead internal link,
so a mistake here is caught before it is published rather than after.

## Conventions

- **English.** The project ships in English first; other languages come later. When
  they do, this site is where a translated locale goes — Docusaurus has first-class
  support for it, and the structure is already locale-agnostic.
- **Every claim is checkable against the code.** If a page describes a flag, an
  option, or a default, that flag, option, or default exists. Pages about behaviour
  are written from the source, not from memory.
- **Tables for reference, prose for reasoning.** The option lists, environment
  variables, and API routes belong in tables. Why a decision was made belongs in a
  paragraph with a reason in it.
- **Admonitions for the things that bite.** `:::warning` and `:::caution` are for
  genuinely destructive or confusing outcomes, not for emphasis. If everything is
  highlighted, nothing is.

## Deployment

`.github/workflows/deploy.yml` builds the site on every push to `main` and publishes
it to GitHub Pages. It needs one repository setting: **Settings → Pages → Source:
GitHub Actions**. Nothing else, and no secrets: the workflow uses the built-in
`GITHUB_TOKEN`.

The build half of that workflow is worth having even before Pages is on: it runs
`npm ci` and `npm run build`, and the build fails on a dead internal link or an
unknown sidebar id. The deploy half fails until a Pages site exists, which a
private repository cannot have on a free account.

To build for a different destination, change `url`, `baseUrl`, `organizationName`,
and `projectName` in `docusaurus.config.js`. Those four lines are the only
deployment-specific configuration in the repository.
